# 已部署的线上变更及回滚

入口：`https://cod.futur-ix.top:8443`。用户确认“你开始”后，以下变更已于 2026-10-30 完成；防火墙未需要修改。

1. 安装本项目代码和隔离 Python 环境到 `/opt/codex-quota-control`，新增专用 API 用户 codexquota。
2. 新增本地 API 服务，只监听 127.0.0.1:8787；独立管理 Token 由 VPS 随机生成，经 systemd LoadCredential 提供。
3. 新增固定操作范围的 root 助手及 sudoers 条目。公共 API 只能读取状态、修改固定定时器、启动固定手动服务和读取过滤后的记录。
4. 为原 service 添加本项目 drop-in，把入口交给执行锁/结果包装器；包装器以原 codexkeeper 用户、原 HOME/PATH 调用原脚本及原参数。新增独立手动 service，共用同一把锁。
5. 原 timer 的基础文件和 08:00/13:00/18:00 时间表保留。后续 App 的修改写入本项目独立 drop-in，原子替换，加载/启停/读回失败则恢复旧配置及状态。
6. 新增独立 Caddy 二进制、专用代理用户及 HTTPS 服务。应用流量只用 8443；80 用于 HTTP-01 证书验证及续期。禁用 TLS-ALPN 验证，不绑定 443。
7. 如现有防火墙确实拦截，仅放行必要的 TCP 80/8443；不重置防火墙、不更改 Xray、SSH 或其他服务。

安装期间短暂停止原 timer，在旧任务空闲时切换，并恢复了原 timer 的启用/运行状态。原脚本及 timer 基础文件的内容校验一致，443 的 Xray 监听进程保持不变。

先在独立 systemd 单元上完成 7 组计划变更、故障回滚和短期到点执行测试；再通过真实 API 完成 7 组计划写入/读回，已恢复 08:00/13:00/18:00。实际手动任务正常跳过活动窗口，并发手动请求返回 202/409，模拟定时服务入口因共享锁忙而跳过。VPS 重启及真机交互未执行，需在适合的环境验证。

回滚：`deploy/rollback.sh` 等待任务结束，停用新 API/HTTPS 服务，删除本项目的 service/timer drop-in 和 sudoers 条目，重新加载 systemd，恢复记录的原 timer 启用/运行状态。原脚本、Codex 认证、SSH 认证均不变；保留管理 Token 和日志供检查。
